# Room realtime transport

GET /v1/rooms/:id/stream uses an Authorization bearer header (fetch streaming; never a token query parameter). Each connection begins with an authoritative reset snapshot and a cursor, then sends fresh server snapshots every two seconds. A reconnect may send Last-Event-ID, but always receives a fresh reset rather than an unbounded replay; no historical event log is promised. The same authenticated GET room endpoint is the polling fallback. Each snapshot rechecks session validity and current pod membership; removal/revocation closes the stream before another snapshot is sent. Limits: 3 streams per account, 50 total, 60-second connections, no buffered backpressure queue. Configure the dedicated proxy to disable buffering for SSE. Network and multi-device browser tests are still required.
