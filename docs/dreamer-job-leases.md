# Durable Dreamer queue protocol

Workers claim ready DAG steps in a SQLite immediate transaction, reserve an attempt and requested output-token budget before the provider call, and receive a unique expiring lease token. Up to four steps globally and three per mission may run concurrently. Only completed dependencies release downstream steps; Critic follows specialists, Chief follows all. A stale/expired/cancelled lease cannot store output. Renewals are bounded by ten minutes per attempt. Expired leases are recorded and retried with backoff when budget permits; a permanent failed dependency cancels queued work and preserves completed/in-flight partial reports. Cancel fences in-flight commits and preserves receipts. Receipts record timestamps, status, sanitized error codes and output SHA-256, not provider secrets or prompts.

No external writes or side-effecting tools are allowed in this queue. A lost lease may cause a repeated read-only model request and provider charges; attempt/token reservations are conservative request budgets, not actual billing. A worker must re-check consent, kill switch, agent status and lease ownership before each call and before storing results. No worker is started by this change.
